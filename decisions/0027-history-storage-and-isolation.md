# 履歴データを設定から分離し、実行アプリごとに保存する

## 判断

貼り付け履歴は Application Support の JSON ファイルへ保存し、履歴の有効化・件数・保持期間は UserDefaults の設定として保存する。保存先ディレクトリには実行中の Bundle ID を使い、通常版と検証版の履歴を分離する。旧 `com.ryotapoi.koecho` ディレクトリの履歴は、通常版に限り、新しい保存先に履歴がない場合に移行する。

## 理由

履歴は長文を含む順序付きデータで、設定値より大きく成長する。UserDefaults に大きな JSON を同居させると設定の読み書きと履歴の管理が結び付く。現在の規模と単純な順序付き一覧には SwiftData の問い合わせ・移行機構も必要ない。独立したファイルなら設定の初期化と履歴の削除も別々に扱える。

固定の保存先を全アプリで共有すると、異なる Bundle ID で起動した通常版と検証版が同じ履歴に触れる。実行 Bundle ID を使い、過去の通常版データだけを通常版へ移すことで、既存データと検証環境の分離を両立する。

## 採らなかった案

- 履歴本体を UserDefaults に置く: 設定値と大量の本文データが同じ保存領域を共有する。
- SwiftData を導入する: 現在の履歴には関係や複雑な検索がなく、管理対象が増える。
- 固定ディレクトリを全 Bundle ID で共有する: 検証版が通常版の履歴を読み書きできてしまう。

## 関連する判断

履歴の書き込み失敗時に利用不可として扱う処理や旧ファイルの移動条件は `HistoryStore` とテストが持つ。ここでは保存領域を分ける判断を定める。
