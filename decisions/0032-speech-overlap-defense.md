# 音声セグメントの再配信に再生成と蓄積比較で対処する

## 判断

キーボード入力や、volatile text をローカル確定するカーソル操作の後は transcriber の再生成を試みる。認識結果が古いセグメントを再配信しても本文を重複させないため、音声由来の確定テキストを蓄積し、その末尾と新しい確定結果の先頭を比較して重複部分を除く。ローカル確定後の replay 抑制状態は [ADR 0021](0021-replay-suppression-state-as-enum.md) の enum で表す。

比較は最大 512 UTF-16 code units とする。1文字の一致は句読点だけを除き、2文字以上の一致はこの比較範囲で除く。蓄積文字列そのものはセッション中に伸びる。`.prompt` 宛ての確定結果は本文用の蓄積に含めない。

## 理由

SpeechAnalyzer の連続ストリームでは、入力操作で区切った後に前セグメントの全文や句読点が次の確定結果に含まれることがある。当時の実験では transcriber 再生成によって重複発生が大きく減ったが、内部バッファの挙動に依存する。音声由来テキストの比較を併用すれば、再生成だけでは防げない再配信にも対処できる。画面上の本文はキーボード編集や置換ルールでも変わるため、比較元にするとユーザー編集と音声再配信を混同する。

1文字の普通の語尾一致まで消すと、無関係な次の語を削る。句読点は重複しやすいため1文字でも対象とする。比較上限は現在の処理範囲を明示するもので、長い再配信を完全に防ぐ保証ではない。

## 採らなかった案

- 表示中の `textStorage` と新結果を直接比較する: キーボード編集や置換後の文字列と音声由来の文字列を区別できない。
- 重複処理を SpeechAnalyzer engine に移す: 入力欄でのローカル確定と表示本文の文脈を engine が持たない。
- transcriber 再生成だけに頼る: 内部バッファの挙動が変わると防御が失われる。

## 現在の限界

volatile text がないカーソル移動では挿入点だけを更新する。認識の再配信・音声の中断が利用者に与える影響は、この ADR では保証しない。同じ語の意図的な反復も重複として除かれ得る。prompt 宛ての確定結果は蓄積しないため、本文へ戻った直後の初回結果では重複を検出しきれない場合もある。これらの対応要否は [backlog の F7・F30・D1](../backlog/backlog.md) に調査タスクとして残す。
