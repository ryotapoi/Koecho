# Koecho 実画面検証の機能導線

ここは実画面で辿る導線の draft。画面の見え方、権限ダイアログ、操作対象は毎回 live state で確認する。Bundle ID の変更だけで CUA の対象が解決すると仮定しない。

| 機能 | ファイル | 主な観測点 |
| --- | --- | --- |
| Custom Script の手動実行 | [custom-script.md](custom-script.md) | `original` → `ORIGINAL`、任意で `Undo Script` |
| 入力パネルのキャンセル | [panel-cancel.md](panel-cancel.md) | TextEdit の編集欄にフォーカスを置いて開き、`Escape` 後の本文不変と再表示時のリセットを別に確認 |
| 音声入力 | [voice-input.md](voice-input.md) | 音声設定、権限、パネルへの転記 |
| ホットキーとペースト | [hotkey-paste.md](hotkey-paste.md) | パネル表示、確定、対象アプリへの貼り付け |

表の項目は個別の機能確認であり、順に操作しただけで一連の操作全体の検証済みとはしない。スクリプト変換の成功と、Escape で貼り付けないことは別の結果として記録する。

## 共通の実行条件

- 使用条件、専用署名 build・起動・doctor・cleanup、隔離の限界は [SKILL.md](../SKILL.md) を正本とする。必要な機能だけを選び、全件の実行や別機能の先行確認は求めない。
- 本人操作を標準とする。CUA は通常の検証では試さず、再評価する場合だけ SKILL.md の条件と対象取得手順に従う。各レシピの画面操作は本人が行い、操作と結果を報告する。
- メニューバー名は通常版も検証版も Koecho。操作対象を区別できない場合や、通常版との hotkey 競合がある場合は操作を止める。検証版の設定・履歴は通常版と分離されるが、同じ Bundle ID の worktree 同士では共有する。
- 許可が必要になった操作と本人の対応を記録する。再ビルド・再起動後の権限維持試験は、それ自体が今回の検証対象である場合だけ行う。
- 証拠は `.tmp/verification/verify-koecho/<run>`。対象、実施者、操作、観測結果、副作用、未確認範囲を残し、cleanup 後も保持する。署名・プロセスの成功から機能の成功を推測しない。各導線は未実証の部分を含む draft であり、本人報告も含め実際に確認した範囲だけを検証済みとする。

変更条件ごとの必須 build / test / 実行確認は [検証の正本](../../../../docs/verification.md) に従う。この機能導線は必須 gate の代替ではない。
