# Backlog

## 運用ルール

- Backlog には、今後着手でき、完了を判定できる作業を `- [ ]` 形式のタスクとして置く。
- 完了したタスクは `- [x]` にし、版を切る変更（バージョンを上げてタグを打つ変更）で消す。取りやめたタスクは消す。
- 対応要否を決める調査もタスクにできる。観察事実だけを残さず、判断したい問いと、判断をもって完了とすることを明示する。
- 粗いメモで起票してよいが、着手前に目的と受け入れ条件を読める粒度へ詰める。
- タスクの行には短い作業名を書き、説明は空行を挟んだ字下げ段落に分ける。
- バージョン番号を付ける場合は SemVer に従う。
- タスクは `###` 見出しでグループに分ける。バージョンが確定したグループだけ、`### v0.1.0 名前` のように見出しへ番号を付ける。
- グループが大きい場合は、`####` 見出しでさらに分割してよい。

## タスク

### v2.0.1

- [x] マイクの入力形式に合わせて音声認識を開始できるようにする

  開始前と transcriber 再開前に、選択デバイス適用後の実入力サンプルレート・チャンネル数へ client PCM 形式を整合させる。確立した capture 形式を初回の SpeechAnalyzer 形式選択と、変換・tap へ一貫して渡す。変換器への各入力バッファの供給は一度だけとする。

  24 kHz hardware / 48 kHz client の不整合、代表的なチャンネル差、形式設定失敗、実 AVAudioConverter による合成 PCM の連続変換、再開と終了時の解放を自動検証する。特定機種や固定形式には限定しない。Sennheiser Profile を含む実機での音声取得・文字起こしは未検証であり、本タスクの完了条件には含めない。本体マイクで文字起こしできない問題は次の別タスクで扱う。

- [x] 本体マイクで文字起こしできない問題を既存の証拠で調査する

  コード・テスト・履歴の静的調査を完了した。入力形式の修正は本体マイクにも適用されるが、報告の原因かは未確定。外部マイクの開始エラー後に設定だけ変更しても認識は再開始せず、パネルを閉じて開き直すと選択した入力元で認識を作り直す。再現条件が分からないため追加の原因修正は保留し、追跡は「再現条件の確認待ち」のタスクで続ける。音声変換エラーの表示は独立した改善として扱う。

- [ ] 音声変換エラーを認識セッションごとに一度表示する

  音声取得後の PCM 変換で明確なエラーが起きたとき、入力パネルに赤字で表示する。正常な出力待ちと変換エラーを区別し、出力がないだけではエラー表示しない。初回の表示で通知済みフラグを立て、同じ認識セッション内では再通知せず、音声処理は継続する。

  新しい認識セッションの開始時に通知済みフラグをリセットする。入力パネルを閉じて開き直した場合や、入力元の変更に伴って認識を再開始した場合を対象とし、認識を再開始しない設定上の入力元変更だけではリセットしない。

  正常な出力待ちは表示されず、変換エラーは同一セッションで一度だけ表示され、処理が継続し、次の認識セッションでは再び通知できることを検証する。本体マイクで文字起こしできない原因の解消とは独立した改善として扱う。

### 再現条件の確認待ち

- [ ] 本体マイクで文字起こしできない報告の再現条件を確認する

  2026-10-20 の報告では「MacBook Pro のマイク」を選んでも文字が入らず、画像では入力パネルが空で設定画面の入力レベルも反応していない。認識中はレベル計測を停止するため、メーターだけでは音声取得の成否を判断できない。原因・解消とも未確認。

  報告環境・版と操作手順を確認する。特に、外部マイクのエラー後に設定だけ変更したのか、本体マイクを選んでパネルを実際に閉じて開き直したのかを区別し、入力形式の修正を含む版でも発生するかを確認する。

  追加情報または再現が得られたら、認識開始・音声取得・変換・認識結果の反映のどこで止まるかを切り分け、追加修正の要否を判断する。判断結果と根拠を記録し、必要な修正を具体的なタスクにするか、追加修正が不要と確認できた時点で本タスクを完了する。
