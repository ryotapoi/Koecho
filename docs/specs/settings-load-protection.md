# 設定と履歴の読み込み失敗時の保護

Script と Replacement の設定は、未設定と保存値の読み込み失敗を区別する。対象は scripts、auto-run の ID・ショートカット・timeout、replacement rules・ショートカット・自動置換の有効状態である。

- 読み込めない単一値は既定値で動作し、起動時の通知に対象項目を含める。timeout は 30 秒、auto-run の ID とショートカットは無効、replacement のショートカットは Control-R、自動置換は有効である。空のショートカット Data は正常な無効値として扱う。
- 読み込めない scripts または replacement rules は実行時には空として扱う。元の保存オブジェクトは、通常の保存・単一設定の変更・追加・編集・削除・並べ替えでは書き換えない。
- 保護中の一覧は編集画面で理由と初期化方法を示し、一覧操作を無効にする。初期化の確認後だけ対象一覧を空の正常データとして保存して保護を解除する。取消は保存値と保護状態を変えない。
- scripts を初期化した後は内蔵スクリプト登録済みとして保存する。内蔵スクリプトは追加メニューから明示的に追加できる。
- 両設定の失敗はアプリ起動時に一度の通知へ集約する。表示済みの通知は、入力パネルや設定画面の再表示では繰り返さない。

置換ルールの通常の編集・適用契約は [replacement-rules.md](replacement-rules.md) を、内蔵スクリプトの通常の登録契約は [builtin-script-ui.md](builtin-script-ui.md) を正とする。

## 履歴

履歴ファイルは、未作成の正常な空履歴と読み込み失敗を区別する。通常版の旧保存先からの移行に失敗した場合も同じ保護状態にし、通常書き込みで空の新履歴を作らない。読み込みに失敗した履歴は実行時には空として扱うが、起動時の整理、記録、消去、削除を含む通常の書き込みでは元ファイルを変更しない。設定と履歴の失敗は、アプリ起動時の一度だけの通知に集約する。履歴のみの失敗でも、ファイルが保護され新規記録が停止していること、履歴設定画面で初期化できることを説明する。

履歴設定画面では利用不可の理由と初期化操作を示す。初期化の確認後に空の履歴の保存が成功した場合だけ保護を解除し、新規記録を再開する。取消または初期化の保存失敗では元ファイルと保護状態を維持する。

正常に読み込めた履歴の Clear All は、空の履歴の保存が成功した場合だけ一覧を空にする。保存に失敗した場合は失敗通知を表示し、従前の一覧と件数、再試行できる Clear All を維持する。読み込み失敗の利用不可状態や初期化画面には切り替えない。成功した消去は再読み込み後も維持される。
