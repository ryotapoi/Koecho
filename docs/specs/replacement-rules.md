# 置換ルール

## 目的

置換ルールは、音声入力や手入力を含む入力パネルのテキストを、ユーザーが定義した表記へ整える機能である。主要機能としての位置付けは[スコープ](../rules/scope.md#置換ルール)を正とし、この文書はその振る舞いを定める。

入力中に結果を見せることと、音声認識が管理する未確定テキストを壊さないことを両立するため、テキストの確定状態に応じて直接置換と preview を使い分ける。この方針の経緯は [ADR 0011](../decisions/0011-debounced-auto-replacement.md) を参照する。手動適用を導入した経緯は [ADR 0003](../decisions/0003-manual-trigger-for-replacement-rules.md) に残る。

## ルールモデルと照合

- 1 つのルールは、置換元と置換先の組である。置換先は空文字列にでき、該当箇所を削除できる。
- 通常の文字列モードでは、1 つの置換先に複数の置換元 pattern を登録できる。空の pattern は照合しない。pattern 中の正規表現メタ文字は文字どおりに扱う。
- 通常の文字列モードでは `Match Whole Word` を選べる。オンの場合は単語全体だけを照合し、オフの場合は単語内の一致も置換する。大文字・小文字を区別しない設定は提供しない。
- 正規表現モードでは先頭の 1 pattern だけを使用し、複数 pattern と `Match Whole Word` は適用しない。置換先では `$1`、`$2` などの capture group を参照できる。無効な正規表現と空の pattern はそのルールを適用せず、入力テキストを保つ。
- 通常の文字列モードの複数 pattern は、長い pattern を先に照合する。これにより、短い pattern が長い pattern の一部を先に消費しない。ルール一覧は登録順に順次適用し、先行するルールの置換結果は後続ルールの入力になる。この複数 pattern の契約と理由は [ADR 0020](../decisions/0020-multiple-patterns-per-replacement-rule.md) を参照する。

### 編集 UI での pattern 行の identity

- 編集 UI の pattern 行は ID を持つ値型（`ReplacementRulePattern`）として扱い、行の追加・削除・並べ替えで入力中の行が入れ替わらないようにする。
- 保存形式は文字列の配列であり、行 ID は永続化しない。読み込み時に新しい行 ID を割り当てる。
- 行 ID は UI 上の identity のためだけに使い、ルール同士の等価比較には含めない。

## 適用契機

### 自動適用

設定の `Auto-replace` は既定でオンであり、入力パネルが表示中でスクリプト実行中でなければ、通常のテキスト変更および音声認識で確定したテキストに即時適用する。オフにすると、通常の入力や音声認識の確定による、この入力中の自動適用だけを停止する。代わりに現在本文の候補へ hover なしで下線を表示する。オンでは確定本文を即時置換し、下線の表示時間を確保するための遅延は設けない。

### 手動適用

置換ルールが1件以上あり、`Auto-replace` がオフの場合だけ、入力パネルに `Replace` ボタンを表示して手動適用できる。スクリプト実行中はボタンを無効化する。ショートカットも設定でき、既定は Control-R である。ショートカットを無効にした場合は、そのキーを置換ルール用には消費しない。新規ルールの追加も明示操作として、追加直後に適用する。これらの明示操作は自動適用と同じ安全分岐を通る。

### この箇所だけの置換

`Auto-replace` がオフの場合、候補の文字上で右クリックし「この箇所を置換 / Replace This Occurrence」を選ぶと、その1か所だけを編集する。同じ文字列の別の出現や他の候補は変更しない。選択範囲の長さに関係なく、右クリックした候補1件が対象になる。これは全文 `Replace` や Confirm とは別の操作である。

- 個別候補は表示中の本文に対して各ルールを独立に照合する。連鎖後の preview 用範囲を編集範囲には使わない。plain / regex / capture / whole-word / 複数 pattern の照合方式は全文適用と同じである。
- 異なるルールの候補が重なる場合は、先に登録されたルールの候補を優先する。一部でも重なる後続候補は、その候補全体を個別 UI に出さない。
- 1回の個別操作で後続ルールを連鎖適用しない。操作後の現在本文で候補を再計算する。例えば `a → bbbb`、`bbbb → c` に対し `a a` の2番目を選ぶと `a bbbb` となり、新しい `bbbb → c` の候補が表示される。
- zero-width regex はクリック対象の文字を持たないため、個別候補の下線・右クリック操作には出さない。全文 `Replace` / Confirm では従来どおり適用する。
- menu 表示後に本文やルールが変わった場合、古い候補は適用せず候補を更新する。自動適用へ変更した場合、スクリプト実行中、IME marked / 音声 volatile 中も個別操作で本文を変更しない。右クリックなどの OS 操作で IME が確定した後は、確定後の通常候補へ戻り個別操作が可能になる。
- 長さの変化は後述の UTF-16 位置対応を使い、音声挿入位置と TextView の選択範囲の両端を補正する。確定本文は `AppState.inputText` と同じ結果へ更新する。
- 本文の編集・内向き同期・script 出力/Undo・ルール編集/削除・Auto-replace の変更で候補を更新する。script 実行中は候補表示を消去し、終了後の本文で再計算する。

### 確定時の適用

Confirm は `Auto-replace` の設定にかかわらず、音声入力を finalize した後に必ず置換ルールを適用する。置換後のテキストは前後の空白・改行を trim し、空になった場合はペーストせずキャンセル相当としてパネルを閉じる。auto-run script を選択している場合も、置換と trim が先に完了したテキストをスクリプトへ渡す。

これは、入力中に直接置換できない状態でも、最終的に貼り付けるテキストへルールを反映するためである。`Auto-replace` は入力中の自動適用だけを制御し、confirm 時の適用は制御しない。

## 入力中の安全分岐と preview

- IME の marked text が存在する間は、テキストを直接変更しない。代わりに一致箇所へ hover なしで下線を描く。置換 Tooltip と専用 hover tracking は提供しない。marked text が確定した後は、Auto-replace がオンなら即時置換、オフなら通常の個別候補表示へ戻る。
- SpeechAnalyzer の volatile（未確定）テキストが存在する間は、置換も preview も行わない。非空 volatile の表示開始時に既存の下線と個別候補を直ちに消去する。volatile 終了後は本文の状態に応じて通常の候補表示へ戻る。
- 挿入位置は UTF-16 の位置として、登録順の各置換前後で対応させる。一致の開始位置は開始位置のまま、終了位置は置換後の終了位置へ写す。一致の内側は開始からの相対位置を置換後の長さまで保持し、削除の場合は削除開始位置へ写す。後続の音声入力と表示上のカーソルは同じ補正済み位置を使う。
- 自動適用中または全文適用を延期する marked preview の範囲は、元の表示本文の UTF-16 座標である。連鎖置換や生成文字列の一部分への後続置換は同じ元範囲にまとめ、中間結果の下線を重ねない。この preview は表示専用で、個別操作は現在本文の単独ルールの候補を使う。
- preview は表示専用であり、入力テキストを変更しない。Confirm で volatile テキストを finalize した後は、前節の確定時適用により置換される。

この非破壊性は、marked text や volatile text の管理中に入力テキストを変更して認識状態を壊さないためのものである。実装上の安全なテキストライフサイクルは [ADR 0011](../decisions/0011-debounced-auto-replacement.md) を判断根拠とする。

保存済みルールを読み込めない場合の一覧保護と初期化は、[設定読み込み失敗時の保護](settings-load-protection.md) を正とする。
