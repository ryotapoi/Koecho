# リリース手順

## 準備コミット

リリース直前に明示的な指示を受けて、対象バージョンの backlog と前回タグから対象コミットまでの差分を確認する。backlog のタスク文をそのまま写さず、最終的なユーザー影響を `CHANGELOG.md` と `CHANGELOG.ja.md` にそれぞれ記す。README の動作環境・使い方・画像も現在の挙動と照合し、必要な箇所を更新する。

完了したタスクは準備コミットまで `- [x]` として backlog に残す。対象バージョンの未完了項目を確認し、残す作業があれば次の版または将来の改善へ移す。完了項目の削除前に、今後も守る理由・制約がコード、テスト、文書、ADR のいずれかに残っていることを確かめる。

Xcode project のバージョンと build number を更新し、両 CHANGELOG・README の更新と対象版の backlog グループ・完了項目の削除を同じコミットに揃える。不要になった backlog の分割ファイル・案内とその参照も整理する。[必須 gate](verification.md) を実行してコミットしたら、一旦停止する。この段階ではタグ作成・push・GitHub Release の公開は行わない。

## 本人による署名・公証

本人が準備コミットから配布用アプリをビルドし、署名・公証を行う。公証関連の作業は本人が担当する。

## タグと公開

本人から公証成功と公開の指示を受けたら、公証したアプリの元になったコミットとバージョン・build number を確認する。そのコミットに `v<version>` タグを打って push し、GitHub Release を作成する。両 CHANGELOG の対象版を基にリリースノートを用意し、本人が公証した配布用アプリの zip を添付して公開する。
