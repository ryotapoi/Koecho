# リリース

版を切る・GitHub Release を公開する共通の手順は `release` skill に従う。本書はこのプロジェクト固有の事項だけを定める。このプロジェクトでは、版を切る commit（準備コミット）の後に本人が署名・公証を行うため、タグは公証の後に付ける。

## 準備コミット

リリース直前に明示的な指示を受けて行う。

- `CHANGELOG.md` と `CHANGELOG.ja.md` の両方に、最終的なユーザー影響を記す。
- README の動作環境・使い方・画像を現在の挙動と照合し、必要な箇所を更新する。
- Xcode project のバージョンと build number を更新する。
- 不要になった backlog の分割ファイル・案内とその参照も整理する。
- 両 CHANGELOG・README の更新と、対象版の backlog グループの削除を同じコミットに揃える。
- [必須 gate](verification.md) を実行してコミットしたら、一旦停止する。この段階ではタグ作成・push・GitHub Release の公開は行わない。

## 本人による署名・公証

本人が準備コミットから配布用アプリをビルドし、署名・公証を行う。公証関連の作業は本人が担当する。

## タグと公開

本人から公証成功と公開の指示を受けたら、公証したアプリの元になったコミットとバージョン・build number を確認する。そのコミットに `v<version>` タグを付けて push し、GitHub Release を作成する。リリースノートは両 CHANGELOG の対象版を基に用意し、本人が公証した配布用アプリの zip を添付する。
